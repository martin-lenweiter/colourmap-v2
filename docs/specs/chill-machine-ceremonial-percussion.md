The companion to `chill-machine-deep-bass-shamanic.md`: where that family
brings the **body** (low frequency, no rhythm), this one brings the
**pulse** (rhythmic percussion at heart-rate tempo). Together they're the
rhythm + bass of a ceremony.

## What ships in this PR

A new **Pulse & Ceremony** category in the Chill Machine
(`components/BinauralTuner.tsx`) with five synthesized layers and an
optional tempo slider that retunes them all together.

| Layer | Character | Synthesis |
|-------|-----------|-----------|
| **Frame Drum** | soft membrane, 4 hits per bar, accent on 1 | Sine 100→70 Hz with exp decay, low-pass 250 Hz |
| **Shaman Drum** | deep slow ceremonial, 2 hits per bar | Sine 60→40 Hz + noise grit at attack, low-pass 180 Hz |
| **Chacapa Rattle** | icaro-style leaf-bundle, swelling tail | Bandpass noise 800-2400 Hz, AM at 24 Hz, swell envelope |
| **Sand Maraca** | rolling 8th-note shaker, on/off-beat accent | High-bandpass noise 3.5-6 kHz, fast attack/decay |
| **Ceremony Heart** | warm slow lub-dub, 72 BPM | Sine 42 + 58 Hz with squared decay, low-pass 130 Hz |

All five pre-render a 4-beat loop at **72 BPM** internally (resting
heart-rate territory). Sharing the same internal tempo means they read
as one ensemble even without a global scheduler.

## Tempo control

A single BPM slider (50-100 range, default 72) appears under the
**Pulse & Ceremony** column on desktop and under the tab header on
phone. It scales `playbackRate` on every active pulse layer
simultaneously, so changing tempo retunes the whole percussion stack
in lock-step. Pitch shifts slightly with tempo (faster = higher,
slower = lower) — this reads as natural for hand percussion (smaller
hand-motion → higher tone).

Implementation:

- `pulseBpm` state + `pulseBpmRef` so audio code reads the live value
- `applyPulseRate(layerId, source)` sets `source.playbackRate.value =
  pulseBpm / 72` at start time
- `useEffect([pulseBpm])` walks `layerNodesRef.current` and updates
  `playbackRate` on every active pulse layer when the slider moves
- Other layer families (waters, drones, etc.) stay at rate 1.0; the
  slider has no effect on them

## Phase alignment caveat

The implementation tunes **tempo** (rate) but not **phase** (start
position). If you enable Frame Drum at t=0 and Shaman Drum at t=2.3s,
they'll share BPM but be 2.3 s out of phase. To re-sync, toggle a
pulse layer off and on.

A real fix would route all pulse layers through a single scheduler
(à la `GrooveMachine.tsx`'s lookahead loop), but that's a larger
refactor. **Marked as v2** below; current behaviour is consistent with
the existing `heartbeat` layer.

## Volume cap

`CATEGORY_VOLUME_CAP['pulse'] = 0.5` — the slider can still travel
0–1 visually, but `setLayerVol` clamps pulse layers to 0.5 max.
Reason: rhythmic percussion is fatiguing at high volume; capping at
half forces the user to add presence rather than dominance.

## App Store licensing — why we synthesize

Synthesized end-to-end. Zero third-party samples. Zero licensing risk.
Everything in `BinauralTuner.tsx` is generated by Web Audio at runtime
from primitive oscillators and filtered noise — Apple, Google, and
any future store can ship this without an attribution claim.

This is a deliberate choice. The alternative — sourcing CC0 frame-drum
and shaker recordings from Wikimedia / Freesound — would be more
authentic but adds:
- license tracking burden in `public/sounds/ATTRIBUTIONS.md`
- ~1-3 MB per layer in app bundle size
- a chain-of-trust audit before App Store submission
- one more thing to break if a sample's license is later revoked

## Optional CC0 sample drop-in (v2)

If you want more authentic percussion later, here's the import path:

1. **Source**: Wikimedia Commons (search "frame drum",
   "tambour", "maracas", "shaker", "rattle"). Filter by Public
   Domain or CC0. Avoid CC-BY-SA (share-alike contaminates user mixes
   in a commercial app) and CC-BY-NC (non-commercial only — App Store
   counts as commercial).
2. **Format**: Trim to 4 seconds, export as `.ogg` (Vorbis Q5).
   Place in `public/sounds/pulse/{frame-drum,shaman-drum,chacapa,
   sand-maraca,ceremony-heart}.ogg`.
3. **Wire**: Add a sibling `REAL_LAYERS` entry per id, e.g.:
   ```ts
   {
     id: 'real-frame-drum',
     label: 'Frame Drum (Recorded)',
     color: '#7A4A2C',
     group: 'real' as const,
     build: (ctx) => buildRealSound(ctx, '/sounds/pulse/frame-drum.ogg'),
   },
   ```
   Add `'real-frame-drum'` to `PULSE_LAYER_IDS` so the BPM slider also
   retunes it (via `playbackRate` on the BufferSourceNode).
4. **Attribute**: Append a section to
   `public/sounds/ATTRIBUTIONS.md` matching the existing `Drums /
   Percussion` convention (filename, source URL, author, license,
   retrieval date).

The synthesized layers stay in place alongside the recorded ones — give
the user the choice: clean synthesized hits vs. recorded character.

## v2 follow-ups

- **Phase-locked scheduler**: route all pulse layers through a single
  Web Audio lookahead transport (mirror GrooveMachine's pattern), so
  enabling a layer mid-bar starts on the next beat instead of
  whenever the toggle was clicked.
- **Real CC0 samples** for users who want authenticity over zero
  licensing burden (see drop-in path above).
- **Time-signature options**: 4/4 by default; add 6/8 (Sufi-style),
  3/4 (waltz), 7/8 (Sami yoik) for cultural breadth.
- **Per-layer rhythm presets**: e.g. Frame Drum could have "steady",
  "doumbek-style", "tribal-roll" pattern variants.
- **Velocity humanization**: ±5 % accent jitter so loops feel less
  mechanical (already present on Shaman Drum's noise grit; could
  generalize).

## Out of scope

- Per-instrument tempo control (one global pulse BPM is the design)
- Tempo coupling with Groove Machine (they have separate transports)
- MIDI export
- Recording / capturing user mixes as audio files (separate feature)
